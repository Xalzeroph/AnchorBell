# Maker 退出安全修复说明

分支：`codex/safety-core`。本次实现截至 `c4fbadd`，本文件随分支一并发布。

## 修复的问题与行为

- 修正被动退出报价：多仓在卖一挂 SELL，空仓在买一挂 BUY。保持 Post-only，live 减仓请求使用 `reduceOnly=true`。
- 退出决策与入场信号解耦：事件处理与独立 250 ms 定时器驱动检查，Healthy 和 Flattening 状态均可处理退出。
- 策略核心、paper/replay 与 live 共用确定性的退出决策；检查价格、数量、精度、最小名义金额及剩余仓位，避免超量减仓。
- 盘口和 mark 分别检查事件时间与接收时间，最长有效期为 5 秒。live 退出使用每 60 秒刷新的 exchangeInfo 规则，静态规则有效期为 120 秒；刷新失败不延长有效期。
- 股票开盘风险与资金费风险采用双截止计划，保留较早截止。完善午间、半日市和跨休市日处理；未覆盖的日历年份阻止新增风险。
- 统一交易写权限：命令行 `--send-orders` 与部署订单许可必须同时开启；未开启时，下单、撤单、退出撤换和停止清理撤单均被禁止。
- 启动要求空仓且没有现有挂单。订单前缀不构成所有权证明；运行中仅操作本进程登记的精确订单身份。
- 核对累计成交、订单终态与仓位快照。成交量回退、超量、缺少成交时间或仓位快照早于最新成交时拒绝继续；未知结果保留待核对订单。
- 事件队列溢出触发风险停止。配置时长结束、Ctrl-C 与运行错误共用清理路径，并报告订单处置和已知或未知的最终仓位。
- 更新中英文说明，并修复路径参数、多余借用、测试模块顺序等静态检查告警。

## 交付边界

Maker-only 的目标是在风险截止前被动减仓，不能保证成交。硬截止后的残余仓位会明确报告；不会伪造成交或自动切换市价单。paper 的成交与过滤器包含显式模拟假设，不能作为交易所接受订单或真实成交的证据。

本批未修改锚点来源、入场算法或交易品种，未实现完整 OMS 持久化、成交事件去重与持续对账。未连接交易账户、运行真实订单或部署服务器；离线测试通过不代表已完成交易所端到端验证。
