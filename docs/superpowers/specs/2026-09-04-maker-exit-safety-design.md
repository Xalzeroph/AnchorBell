# Maker 退出安全设计（安全核心第一批）

状态：已在 `codex/safety-core` 完成实现与离线验证；尚未连接交易账户、部署或执行真实订单。

基线：`dadc1ec6ba4627efbd5a47e8354ef5a0f10c8dfa`。
目标分支：`codex/safety-core`。

## 1. 目标与交付边界

先修正当前 Maker 退出链路，使退出不依赖入场信号、退出报价不主动吃单、只读运行不产生交易写操作。策略、模拟盘和 live runner 共享确定性的退出决策。

本批保留 Maker-only、生产双开关、行情过期保护和仓位上限。既不连接交易账户验证，也不部署到服务器。自动化验证全部使用离线输入和本地测试。

后续交付单独设计：订单事件去重与持续对账、可选紧急吃单退出、L2 队列模型及统计参数校准。本批不替换整个 OMS，不修改锚点来源、入场算法或交易品种。

## 2. 现有证据

- `engine/src/bin/anchorbell_live.rs` 的 `GateDecision::Flatten` 分支对多仓使用买一卖出、对空仓使用卖一买入，但 `place_order` 最终仍调用 `place_maker_order` 发送 `LIMIT + GTX`。这种可立即成交的价格与 Post-only 语义冲突。
- `engine/src/paper.rs` 的 `evaluate_symbol` 使用相同的退出报价方向，而 `place_symbol` 要求买单不高于买一、卖单不低于卖一。因此普通非零价差下，模拟退出意图会在本地被拒绝。
- live runner 先调用 `make_intent`，无入场意图便跳过 `supervisor.evaluate`；平仓决策由此依赖入场信号。
- live runner 只在 `Healthy` 状态执行上述决策循环；进入 `Flattening` 后缺少相应的独立持续退出调度。
- live runner 平仓分支的 `cancel_symbol_orders` 调用位于 `args.send_orders` 判断之前；只读运行存在交易写操作路径。
- `lifecycle.rs` 不接受 `CancelRequested` 期间的成交事件。这是下一批 OMS 设计需要覆盖的问题，本批不把修改一个未接入 runner 的类型等同于完成实盘状态机修复。

以上是静态调用链检查结果，不是交易所端到端验证结果。

## 3. 方案取舍

推荐分层修复：先完成可独立验证的 Maker 退出链路，再统一 OMS，最后讨论紧急吃单模式。优点是本批不改变已有执行许可与 Maker-only 契约。

仅修正两处报价方向也能解决部分问题，但无法覆盖无信号时不退出、退出调度中断和只读撤单问题，因此不作为完整交付。

立即引入吃单双模式需要同步改变 REST/WebSocket 校验、订单事件校验、风控与文档，不适合和现有缺陷修复混在一起。未来模式应命名为 `EmergencyReduce`，不能使用 `GuaranteedFlat`：断网、停牌、无流动性、限价保护或交易所拒绝时，任何订单类型都不能保证归零。

## 4. 确定性退出决策

### 4.1 共享接口边界

在 `engine/src/strategy/flatten.rs` 扩展纯退出决策，并由 `strategy/mod.rs` 导出。输入包含：当前时间、现有 `DualFlattenPlan`、标的标识、已确认净仓位及其可信状态、买一卖一及接收时间、最大行情年龄、明确的本地订单处理状态、有效的交易所订单过滤器和价格/数量缩放参数。Paper 使用显式配置的对应约束，不把缺失过滤器当作无限制。

输出显式区分：允许正常交易、停止开仓、等待撤单/对账、提交被动减仓意图、无仓位、截止后残余风险、输入无效或行情过期。

该模块不访问网络、不读取凭据、不读取系统时钟、不更改真实仓位。调用方提供时间和快照；live 与 paper 使用相同规则。

### 4.2 报价与数量

- 多仓减仓：卖出，价格为卖一。
- 空仓减仓：买入，价格为买一。
- 零仓位：不创建订单。
- 所有减仓意图保持 Post-only；live 请求另外必须设置 `reduceOnly=true`，paper 必须保留相同约束。
- 要求 `0 < bid < ask`。零价差、倒挂、无效价格、未来时间戳和过期行情不产生退出订单。
- 不以 mark/index 的更新时间代替订单簿的新鲜度。
- 减仓数量不得超过可确定的剩余净仓位。`i64::MIN` 等不可安全取绝对值的仓位必须报错，不能饱和成另一个数继续交易。
- 数量按实际交易所过滤器向下取整；超过单笔最大数量时分批。不满足最小数量或名义金额的尾仓必须报告，不向上取整到可能反向开仓的数量。
- 价格与数量使用整数 tick，名义金额计算必须按各自缩放正确换算并检查溢出；过滤器缺失、过期或不一致时阻止下单并报告。
- 不把提交、接受或撤单成功当作成交；仓位只能由已确认的账户/成交事实更新。

### 4.3 时间与状态

继续复用现有开盘与资金结算双截止计划，先到的事件决定停止新增风险和开始减仓的时点；不得引入另一套不一致的时间常量。

退出检查必须在处理每个市场/账户事件后及独立的 250 ms 本地调度 tick 执行，不依赖 `make_intent` 是否生成入场信号。`Healthy` 和 `Flattening` 均能进入退出检查；未知账户状态仍不得提交订单。

进入减仓窗口后禁止新增风险。已有有效同价同数量减仓订单保持排队位置，不每个 tick 撤换。需要撤换时先确认旧单结果并更新剩余仓位，再创建新单。结果未知时停止新单并报告，不能猜测订单已取消。

到达硬截止仍有仓位时，进入显式残余风险状态，继续接收账户及订单事件，报告残余数量、原因和相关订单；不宣称平仓成功，不自动切换成市价订单，不因到期自动退出进程，也不恢复开仓。未终结减仓订单仍需跟踪。若用户主动停止或已配置的运行时长结束，先报告残余仓位与挂单处置结果，再退出，不宣称风险已解除。

## 5. 只读和生产许可

`--send-orders=false` 表示禁止交易写操作，包括下单、单笔撤单、批量撤单、退出阶段撤换以及退出清理阶段撤单。只读账户查询、行情订阅和必要的连接管理不视为交易写操作。

提交和撤单统一从同一个执行许可边界进入，不能只在个别调用点依赖条件判断。测试必须验证拒绝许可时交易写适配器的调用次数为零。

保留现有 Testnet 默认环境和 Production 显式确认规则；新增退出逻辑不能扩大凭据、账户、标的或订单所有权的范围。只处理当前策略已跟踪且归属明确的订单；无法确定所有权时停止并报告，不顺带撤销同账户其他策略的订单。

## 6. 改动范围

| 文件/模块 | 职责 |
| --- | --- |
| `engine/src/strategy/flatten.rs`、`strategy/mod.rs` | 共享退出决策与状态输出 |
| `engine/src/execution/supervisor.rs` | 将退出检查与入场意图校验解耦，保留未知状态保护 |
| `engine/src/bin/anchorbell_live.rs` | 事件/timer 调度、退出执行、残余风险上报 |
| `engine/src/execution/` 下的小型执行许可模块 | 统一控制交易写操作，不放宽底层 Maker 校验 |
| `engine/src/paper.rs` | 使用共享退出逻辑，不凭空生成退出成交 |
| 同模块单元测试及必要的 `engine/tests/` 离线集成测试 | 检查跨层行为与副作用 |
| `README.md`、`README.zh-CN.md`、运行手册 | 将按时归零描述改为退出目标，明确 Maker 残余风险与只读语义 |

遵循 Rust 2021，保持现有依赖，不引入新生产依赖。仅为本批职责提取小模块，不进行无关目录重构。

## 7. 测试与验收

每个行为先增加能在基线失败的测试，确认失败原因后再实现。

1. 买一 98.80、卖一 98.90、多仓 10：生成卖一 98.90 的 Post-only 减仓意图，数量不超过 10。
2. 同盘口、空仓 10：生成买一 98.80 的 Post-only 减仓意图；零仓位没有订单。
3. 零价差、倒挂、过期盘口、未来时间戳与不可安全处理的仓位均不得生成订单。
4. 即使入场信号为空，进入开盘/资金减仓窗口仍触发退出决策；仅 timer 推进也能触发。
5. 已进入 `Flattening` 后仍能处理减仓订单和残余仓位；有效订单保持不动，不循环撤换。
6. 撤单结果未知时不创建替代订单；确认部分成交后按剩余仓位更新数量。
7. 所有只读路径，包括平仓、断线、启动恢复和退出清理，交易写调用次数均为零。
8. Paper 非零价差下可以接受上述合法减仓单，但只有兼容成交事件才能改变仓位。
9. 到达截止仍有仓位时产生残余风险记录，不制造成交或平仓成功事件，不恢复开仓。
10. 原有 Maker-only 与 Production 许可拒绝测试仍通过。

验收命令：

```text
cargo fmt --all -- --check
cargo build --workspace --locked
cargo test --workspace --locked
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
```

离线通过只证明这批实现满足测试契约，不代表交易所接受订单、不保证成交或盈利，也不授权生产验证。
